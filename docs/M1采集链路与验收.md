5. 真实 PostgreSQL 隔离 schema 并发验收、浏览器隐私回归、静态检查和文档。

## M1 补充决策

- 身份最小元数据（站点化 visitor_key、epoch、first_seen_pv_at）不跟随缩短后的成员窗口提前清理；至少保留至最后活动后 90 日，且存在会话/事实引用时不得删除。M2 清理必须遵守。新老访客指当前身份 epoch 内首次可观测 PV，清除/过期 cid 会产生新身份。
- 建站设置：名称、精确 Origin 白名单、IANA 时区、保留窗口及采集规则。PATCH 仅允许名称、Origin、enabled、采集规则；时区、内部 ID、密钥版本和身份 epoch 不可批量修改。保留变更预览和实际清理属于 M2，M1 不提供无预览的缩短操作。
- 规则只支持有界路径前缀排除、默认敏感段脱敏、UTM 白名单开关、机器人排除、history/hash/manual。禁止任意用户正则。规则快照保留至全部引用事实退出幂等窗口。
- 单应用共享连接池最大 8；采集最多 4 个执行中、每站最多 2 个；最多 64 个等待及执行请求、每站最多 16 个，按站轮转。管理最多 2 个执行请求；后台关闭任务单连接、轮转站点。连接获取 750ms、锁等待 750ms、SQL 1500ms、事务 4000ms、整请求 5000ms；取消销毁活动连接并回滚。
- 初始每站 60 请求/秒及 600 事件/秒；每 cid 120 请求/分钟、突发 60，覆盖 10 个标签的常规心跳；每站化 IP 600 请求/分钟、突发 120。内存限流键有界、定期过期，不持久化 cid/IP。5 站点为验收规模，不是硬编码产品上限。
- 会话关闭每 60 秒执行；每轮按站点轮转、每站最多 20 条，复用站点 → 访客 → 会话锁序。重复事件/累计心跳不更新访客、会话、成员或脏桶。
- 管理员采用 Argon2id（32MiB / 3 次 / 并行 1），哈希并发为 1；管理 token 只存摘要，CSRF 使用独立密钥。生产仅 HTTPS Secure cookie；本地 HTTP 使用独立开发 cookie 名称。

## 验收证据

冻结锁文件离线安装、类型检查、Oxlint、Prettier、四包构建和 `git diff --check` 通过。111 项测试全部通过：38 单元、9 PGlite、41 真实 PostgreSQL、19 SDK 浏览器、4 既有页面浏览器。SDK 为 10,365 字节，gzip 4,291 字节，低于 8KiB 目标。

环境：Node 24.18.0、pnpm 10.20.0、PostgreSQL 17.11、Google Chrome 151.0.7922.71。机器可读摘要见 [m1-collection.json](verification/m1-collection.json)。实际执行：

## 已实现接口与运行方式

| 接口                                  | M1 行为                                                             |
| ------------------------------------- | ------------------------------------------------------------------- |
| POST `/api/v1/auth/login`             | 精确管理 Origin、登录限流、单并发 Argon2id、生成管理 cookie 与 CSRF |
| GET `/api/v1/auth/session`            | 检查 7 日绝对期限及 24 小时闲置期限，返回身份和稳定 CSRF            |
| POST `/api/v1/auth/logout`            | Origin + CSRF；数据库撤销会话后清 cookie                            |
| GET/POST `/api/v1/sites`              | 认证后的列表/创建；公开 ID 随机生成                                 |
| GET/PATCH `/api/v1/sites/:site_id`    | 详情、配置版本快照；暂停排空；维护期拒绝修改                        |
| GET `/api/v1/tracker-config/:site_id` | 同意后由 SDK 请求；精确 Origin、隐私信号检查，只返回公开采集规则    |
| POST `/api/v1/collect`                | JSON / text/plain JSON；≤20 条、16KiB；整个批次提交后 204           |
| POST `/api/v1/heartbeat`              | 单页面累计值；每次最多投影 15 秒区间，多标签按并集计时              |
| OPTIONS 采集端点                      | 精确 Origin 预检；不允许 credential CORS                            |
| GET `/tracker.js`                     | 提供本地构建 SDK；无框架依赖                                        |

站点创建必填 `name/primary_origin/allowed_origins`，可选 `timezone/rules/raw_retention_days/member_retention_days/aggregate_retention_days`。Origin 必须是规范化的完整 scheme/host/port，主 Origin 必须在白名单内；不接受路径、通配符、`null`。时区经 PostgreSQL IANA 名称校验，创建后不提供随意修改。

PATCH 白名单为 `name/primary_origin/allowed_origins/enabled/rules`；rules 是完整对象，字段为 `routing_mode/excluded_prefixes/redact_identifiers/allow_utm/exclude_bots`。每次修改新增 rule_version 快照，保留旧幂等解释规则。`sites.config.identity_epochs` 记录初始 visitor/IP epoch 与生效时间，PATCH 保留内部元数据；没有开放密钥轮换接口。

应用启动配置、首次创建独立密钥、管理员 stdin/密码文件命令见 [README](../README.md#m1-本地配置与管理员)。本次未在默认开发 schema 执行 002、未创建实际管理员、未修改现有 `.env` 或任何既有密钥；操作员可按 README 显式完成本地升级。`pnpm dev` 会构建共享包和 SDK；关闭 worker 在 API 进程每 60 秒执行，测试调用相同实现而不等待真实一分钟。

| 隐私/真实链路     | 未同意零存储访问/零采集；GPC/DNT/退出；异步撤销；可信点击与程序事件区分；真实 HTTP 浏览器 PV/互动/导航/心跳入 PostgreSQL；事实无原始 cid/IP/敏感 URL |

所有 PostgreSQL 测试创建随机 schema，结束后只清理测试 schema；不把 PGlite 的设计探针当作并发证明。浏览器真实链路使用独立 HTTP 宿主与 API 端口以及测试站点，显式关闭测试站点的 Headless 机器人过滤。其余 SDK 浏览器测试模拟 HTTP 响应，以便控制失败、重试和配置；BFCache 验收使用浏览器派发 persisted/pageshow/popstate 场景，未声称验证所有浏览器的真实缓存调度。

R09 的完整 30/90/365 日目标保留规模、持续 8:1 心跳负载、写放大/磁盘/WAL/P95/P99 和崩溃恢复仍在 M5；一万条索引夹具不是生产容量结论。跨午夜归属已由“锁后接纳时间 + 按站点时区落日”的实现及时间顺序测试覆盖，尚未进行等待实际午夜的长期观测。M2 仍须实现查询、聚合、独立冻结、保留清理、删除任务及对账；诊断详情/设置 UI 在 M2/M3，可信代理与生产容器/TLS 在 M4。前端仍是初始化预览页。

实现依据：[PostgreSQL 17 超时参数](https://www.postgresql.org/docs/17/runtime-config-client.html)；[Node.js crypto Argon2](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoargon2algorithm-parameters-callback)。本机实际 Node 24.18.0 已验证原生 Argon2id 可用。
