## 已交付加固（2026-11-06）

- 在恢复闸门、解析请求体和申请数据库连接之前限制全局在途请求为 64；过载返回 503 和 Retry-After，响应结束或连接断开释放额度。健康检查独立可用，SSE 占用的额度随断开释放。
- 管理 API 默认禁止缓存，补充 nosniff。诊断接口提供固定内存的响应分类/耗时桶、RSS/heap、在途数和连接池状态；只允许管理员读取，不保留 URL、查询参数、cid、IP 或请求体作为指标标签。
- 只读 SQL 使用设计规定的 3 秒语句期限，写事务保持 1.5 秒，事务总期限仍为 4 秒。部分日精确去重增加显式时间范围条件，使 PostgreSQL 可以直接使用事件时间索引；跨日、DST、首日与过期语义回归通过，未声称压测后性能达标。
- 修复 Firefox 跨标签首次 cid 竞态：在 Web Locks 内跨任务边界同步 localStorage 快照；保留无存储时的内存身份与撤销同意保护。
- ECharts 固定升级至 6.1.0，修复 [GHSA-fgmj-fm8m-jvvx](https://github.com/advisories/GHSA-fgmj-fm8m-jvvx)。生产依赖复审未检出漏洞。
- 构建使用 Node 24.22.2；API 运行镜像改为同版本 Alpine，保留 uid 1000、只读运行和能力限制，并移除运行时不需要的 npm/yarn。生产依赖为 JavaScript，已在真实容器中验证登录、站点、采集及维护进程启动；本机开发回归使用 Node 24.18.0。
- 刷新并固定 Nginx 1.30.6 与 PostgreSQL 17 Bookworm 镜像 digest；数据库主版本和系统系列保持一致。镜像清单和扫描结果见 [安全报告](verification/m5-image-security.json)。
- 备份、恢复共用 Compose 参数生成器；使用覆盖文件时通过 `WEBPULSE_COMPOSE_OVERRIDE_FILE` 指定同一个文件，避免运维命令按另一套资源配置重建数据库。该问题由隔离验收探针发现，修复后的备份已执行；完整窗口恢复因用户停止压测未完成。
