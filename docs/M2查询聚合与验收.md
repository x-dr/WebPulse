# M2 查询、聚合与验收

日期：2026-11-05。状态：已完成本地实现与验收。沿用 M0 冻结统计/删除契约，范围包括查询、重算、独立冻结、保留清理、删除执行器及重建对账。M3 后台页面与 M4 SSE/部署未在此阶段实施。

## 交付

- 新增不可变追加迁移 `003_reporting.sql`：六层覆盖、缺口、扫描游标，汇总版本/revision/冻结时间，持久化删除任务、加密 outbox、重建桶及永久 tombstone。任务和 outbox 不随站点级联删除；旧站点补齐覆盖，旧汇总未经过本实现计算时不直接视为可信。001/002/reference 均保留。
- 报表使用短 `REPEATABLE READ READ ONLY` 快照读取站点、覆盖和事实；认证续期在此前独立短事务执行。分页、排序、日期、时区、筛选都有限额和白名单。日期最多 366 个自然日，趋势最多 1500 点；分钟/小时原始趋势按整个范围一次分组查询。
- 完整自然日的范围 UV/IP 从日成员统一 DISTINCT；部分日使用实际区间原始 PV，和完整日成员 UNION 后再次去重。新老以整个范围起点分类，缺少首次 PV 快照时不猜测。跨身份 epoch、窗口过期、覆盖缺口或建站前范围明确返回 null/reason。
- 已冻结整日读取同版本总量及排行；未冻结日读取事实，互斥拼接。日趋势允许读取冻结 UV/IP 标量，但不将趋势点相加充当范围 UV/IP。小时趋势保留 UTC 整点及 DST 重复小时；非整小时偏移时区的首尾片段回查原始 PV，标为 `complete=false`。
- 同期比较按站点自然日平移，涉及今日时上一周期裁剪到相同墙钟时间；重叠时间取第一次，缺失时间向后移动实际缺口，返回 UTC 边界、offset、DST 调整和关闭截止。历史部分日的已结束分母使用实际 `closed_at <= comparison_as_of`，PV 右边界严格排除。两个完整历史周期使用当前快照最终会话。
- 聚合在专用连接取得同数据库/schema 的维护 advisory lock，再启动短 RR 事务。完整替换总量、页面/来源排行和成员；总量与排行共享 revision，校验页面 PV 与来源会话合计后按脏版本条件清理。冲突整笔重试至多 3 次，绝不在扫描前锁住热脏行。零桶保留明确总量。
- 冻结枚举独立于 dirty 队列：从观测起点逐个补齐小时/自然日，也复查已有非最终桶；结束后 12h30m、会话均关闭且覆盖可信才冻结。结果、finalized_at、枚举游标和连续水位同事务提交。暂停站点继续维护；缺口、版本不明、事实不足阻止冻结，不能将已过期事实重算成零。
- API 进程启动后立即维护，以后每 60 秒一次。关闭会话和其余维护串行，单进程后台最多占一个连接；维护连接 finally 解锁才归池。每轮轮转最多 5 站，每站最多 5 个重算/冻结尝试，删除最多 10 个有界批次；单站失败保留待办并继续轮转。全池上限仍为 8。
- 心跳和新互动仅改变开放会话，已关闭会话统计不变，因而不再反复标脏；PV 与实际关闭仍同事务标记有关开始桶。持久化时钟回拨或相对单调时钟显著跳变时记录 `clock_unstable`，暂停冻结/清理，连续两次稳定采样后恢复。
- 保留清理取配置、两个连续冻结水位及未解决缺口的保守交集。先提交不可查询 gap 与固定 target，再按稳定主键顺序分批删除，持久化阶段/主键/批次游标；全部完成后才推进 actual `available_from`、清除 gap。一次最多 500 行、SQL 1500ms、锁等待 200ms、事务 4s。无数据也推进覆盖；扩大保留不会复活旧数据。跨日依赖行可物理保留，但不能扩张查询能力。身份元数据至少保留至最后活动 90 日且无事实/会话引用。

当前不启用进程报表缓存，每次查询都校验维护状态与覆盖；保留 `private, no-store`。这避免删除/保留变更时旧缓存绕过闸门；缓存及更大规模调优在 M5 混合负载证据之后评估。

## API

统计基础路径 `/api/v1/stats`，均需管理 cookie 与 `site_id/start_date/end_date`，日期为 `[start_date,end_date)`。可选 timezone 必须等于站点时区。所有响应包含站点、时区、指标版本、as_of、有效 UTC 范围、覆盖 revision 和实际可用边界。

首日边界修正（2026-11-06）：当查询起点和 `observed_from` 属于站点时区的同一自然日，且查询截止晚于接入时刻时，从 `observed_from` 起计算总览、访客、排行与趋势。`meta.start_utc` 保留请求起点，新增 `effective_start_utc` 表示实际统计起点，后台提示首日从接入时刻起统计。首个未覆盖整桶的趋势点为 `complete=false`。更早日期仍返回 `before_site_created`；缺口和保留窗口不足继续返回原有不可用原因，不移动边界掩盖数据损失。所有报表响应均包含 `meta.unavailable_reasons`；趋势各点的具体原因仍保留在 `points[].reason`。

| 接口            | 行为                                                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------ |
| GET `/overview` | PV/UV/IP、会话/已关闭/跳出、比率/时长、新老、15 分钟活跃及所有可比较指标的上一周期变化；0 基期与不可用分开返回原因 |
| GET `/visitors` | 范围 UV、新老及比例；零 UV 无定义的比例为 null                                                                     |
| GET `/trend`    | `granularity=minute/hour/day`；metric 为共享契约枚举；空且有覆盖为 0，未来点省略，不可用点带 reason                |
| GET `/sources`  | 渠道、host、UTM 会话排行，支持 channel/referrer_host/utm_source/utm_medium/utm_campaign 精确筛选                   |
| GET `/pages`    | `mode=view/entry/exit`，可选 `search` 路径子串，最长 128 字符                                                      |
| GET `/entries`  | pages 的 entry 兼容别名，支持 search                                                                               |

排行参数：`page>=1`、`1<=page_size<=100`，默认 1/20；`sort=count/name`、`order=asc/desc`，默认 count/desc，使用维度决胜保证稳定分页。share 分母始终是整个范围对应单位的总数；筛选和分页不重新归一化。`other_count` 包含未在本页显示的计数。entry 总数等于范围开始会话数，exit 等于其中已结束会话数。

## 删除与 journal 闸门

删除目标使用独立 AES-256-GCM 密钥加密，含稳定 public ID、不可变 cutoff、全部 visitor key/epoch 及范围；无原始 cid/IP/URL。需要配置可选 `DELETION_ENCRYPTION_KEY_FILE` 和 `DELETION_KEY_ID`；缺失时删除受理返回 `503 deletion_key_unavailable`，其他功能无需此密钥。密钥须稳定托管且与三个 HMAC 密钥独立，不能覆盖现有密钥或用临时值替代。`.env.example` 只有说明，本次未生成或修改任何实际密钥。

执行顺序为 journal → facts → sessions → visitors → members → aggregates/site → verify/complete。事实按 interaction、PV 依赖顺序，按稳定主键有界删除；任务 cutoff、游标、删除计数与批次同事务提交。worker 使用持久化租约和递增 generation，发布重建与提交任务状态都验证当前 token。失败回滚本批并持久化脱敏错误/退避时间，重试不移动截止、不重复累加；最多 8 次后 blocked，保持禁用。单访客删除重建所有受影响日/小时成员、总量与排行，保留其他访客共享 IP，并将受影响冻结游标/水位退回重建起点；对账完成后清 gap，仍需管理员显式恢复采集。

**M4 独立清单存储适配器尚未接入。运行入口不注入 journal，任务因此停在 journal/retry_wait，不能执行任何破坏性批次。** 外部清单未确认时不通过数据库 outbox 代替确认。测试通过注入幂等内存 journal 验证状态机；它不是生产清单，也没有数据库备份恢复证明。

运维入口（本次没有在默认开发 schema 运行这些命令）：

```bash
cd /root/WebPulse
# 显式迁移后，API 启动会定时维护；单次维护可用：
pnpm maintenance:run
# 修复密钥/journal 后，沿原 phase/cutoff 重试已有任务：
pnpm deletion:retry JOB_UUID
```

单访客删除只提供 CLI，原 cid 使用隐藏 stdin；站点和幂等 UUID 可作参数：

```bash
cd /root/WebPulse
read -r -s -p '待删除 cid: ' WEBPULSE_DELETE_CID
printf '\n'
printf '%s' "$WEBPULSE_DELETE_CID" | pnpm visitor:delete SITE_PUBLIC_ID IDEMPOTENCY_UUID
unset WEBPULSE_DELETE_CID
```

CLI 先在维护锁下暂停并排空，验证整个已观测区间的重建依据；一旦清理过必要事实或存在 gap，保守返回 `409 deletion_not_exact`，无破坏性删除，保持暂停。当前 epoch 使用现有 HMAC 密钥；旧 epoch 需要受限 `VISITOR_HMAC_HISTORY_FILE`（JSON 映射 epoch 到 64 hex 密钥），缺任何相关密钥返回 `identity_epoch_key_unavailable`。不会自动扩大到整站删除。任务完成后同 cid 的后续新接纳数据不受永久封禁。
