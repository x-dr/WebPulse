# 统计与采集契约（M0）

版本：1.1.0；冻结日期：2026-11-04。本文是主技术文档第 6–8、11、13 节的实施约束，处理 R01–R05、R07，并固定其依赖的最小时间语义。数据库迁移和业务代码在 M1/M2 实现；冻结不代表功能已上线。验收编号见 [M0 验收](../docs/M0设计冻结与验收.md)。

## 1. 接收时间与事务入口

`received_at` 定义为取得站点锁、访客锁后首次接纳新事件的数据库时间，使用一次 `clock_timestamp()`；`occurred_at=received_at`。HTTP 到达时间只用于请求耗时诊断，不能拿排队前时间回填历史桶。一个批次共用接纳时间，按数组顺序处理事件；重复事件保留首次存储值。这明确了原文“首次成功接入”的含义。

采集使用 `READ COMMITTED`。顺序为：受限解析及 Origin/隐私预检 → 站点 `FOR SHARE` 并复核最新配置 → 事务级访客 advisory lock → 已存在访客 `FOR UPDATE` → 事件判重 → 会话 → 页面 → 按 `(site_id, grain, bucket_start)` 排序的脏桶。访客锁键由带用途前缀的站点 ID 与访客键派生为固定 64 位值；碰撞只多串行，不可跳过身份/站点复核。它保护尚无访客行的首次并发请求；判重前不得用 upsert 修改访客活动时间。

取锁后的时间小于该访客最近活动时间时，回滚并返回 `503 clock_regressed`，不把时间倒退写入事实；重试不改变已确认事件。事件和心跳共享每访客单调 `activity_seq`，只在接受新活动时递增；最近页面按 `(received_at, activity_seq)` 决胜，不能依赖只覆盖 events 的 `ingest_seq`。这些字段由 M1 新迁移补充。

同一事件 ID 的一致性使用 `fingerprint_version=1`：固定字段顺序、UTF-8 JSON、缺省值显式归一化，计算 SHA-256。包括访客键/epoch、type、page_view_id；PV 另含清洗后的 origin/path、referrer host、白名单 UTM、reason；interaction 另含 interaction_kind。排除接收时间、client_ts、网络 IP、HTTP 头和批次位置。重试按已存规则版本清洗比对；规则规范化器保留到幂等窗口结束。不可为了重试持久化原始 URL/cid。现行隐私、Origin、站点状态仍优先校验。

M1 必须有整请求 5 秒上限和取消后的事务回滚，禁止挂起事务在数小时后提交旧时间事件。连接、语句和事务的分层限额在 R10 落地。时钟回拨或明显跳变时暂停冻结/清理并报警，恢复稳定后从持久化游标补扫。

PostgreSQL 的 `now()` 固定在事务开始，取锁后实际时间需使用 `clock_timestamp()`；以上接纳点与顺序是项目决策。[时间函数](https://www.postgresql.org/docs/17/functions-datetime.html#FUNCTIONS-DATETIME-CURRENT)

## 2. 禁用、删除与在途采集（R07）

所有 collect/heartbeat（包括重复事件）在业务事务内执行：

```sql
SELECT id, enabled, config, rule_version
FROM sites WHERE public_id = $1 FOR SHARE;
```

锁内复核 `enabled`、删除/维护状态、Origin 和过滤规则；被禁用返回 `403 site_disabled`，删除任务中的站点返回 `409 site_deleting`。查询不到返回 `404 site_not_found`。入口缓存只可用于快速拒绝，不能授权写入。持锁直到业务提交或回滚。采集不得在持有共享锁后更新 sites 的采集时间等字段；诊断信息从事实推导或写独立状态，避免锁升级死锁。

禁用事务先 `SELECT ... FOR UPDATE` 同一站点，等待持有共享锁的采集结束，再更新 `enabled=false` 和配置版本，提交后清缓存并返回成功。其**线性化时点是该事务提交**：旧请求只能在此之前提交；此后取锁的请求看见新状态并拒绝。HTTP 回包可能因网络迟到，不表示业务在禁用之后提交。普通暂停仍允许读取历史报表。

删除的第一笔事务使用同样站点锁，原子写入禁用、删除状态、持久化任务和加密删除意图；提交后才返回 202。之后保持禁用直到完成或人工处理失败；恢复开关在任务未完成时返回 `409 maintenance_in_progress`。删除、重建期间阻止该站点报表和 SSE，使用 `409 site_maintenance`，避免提供部分删除结果。详见 [删除契约](删除与覆盖契约.md)。

共享站点锁彼此兼容，不把不同访客串行化。禁用使用冲突写锁；不能换成只保护键的 `FOR KEY SHARE`。锁等待超时则整个管理事务回滚，返回可重试失败，不能声称暂停成功。[PostgreSQL 行锁冲突表](https://www.postgresql.org/docs/17/explicit-locking.html#LOCKING-ROWS)

## 3. 页面导航与清洗（R03）

SDK 分开维护内存中的 `navigation_identity` 和发送用的 `report_path`：

- 自动 History 模式 identity 使用浏览器解析后的 Origin + **未脱敏 pathname**，保留大小写、末尾斜杠、编码形式。默认 query/hash 均不参与；UTM 变化本身不触发 PV。
- 首版仅支持 `routing_mode=history|hash|manual`。hash 模式以去除 hash 内 query 的路由 path 作为 identity/path 输入；普通 query 与 hash query 仍忽略。首版不提供 query 导航白名单；需要 query 驱动路由的应用使用 manual 模式。
- 同一微任务内多次 History 调用只计最终逻辑地址；跨轮次 `/product/123` → `/product/456` 产生两个 page_view_id，发送路径均可为 `/product/:id`。同一 identity 的重复 replaceState 不新增 PV；A→B→A 的不同轮次计三次。
- identity 仅在已同意后的 SDK 内存短暂保存，绝不上传、记录日志或存储。发送队列只含清洗结果；被排除路径仍更新当前 identity，但无 PV/心跳/互动。之后回到允许页面按一次新导航处理。
- manual 模式每次显式调用表示一次访问，调用方负责去重；禁用自动 History 捕获。BFCache 恢复使用一次恢复 token 合并同次 pageshow/popstate；resume 是新访问，不受相同 identity 抑制。

URL 清洗、保留路径长度和隐私规则继续遵守主文档 8.5。用清洗后的路径判重是禁止的。M1 需测试 query/hash 默认忽略、hash 模式、手动模式、BFCache 与敏感路径不外泄。

## 4. 关闭会话与互动（R04）

先按第 1 节锁序验证所属站点/访客、查询事件幂等记录，再处理新事件。处理时间 `t` 在获取相关锁后取值；会话有效条件同时为 `status=open`、`t < last_activity_at+30min`、`t < started_at+12h`，等号即失效。有效性检查与写入在一个事务；关闭任务遵守相同锁序。

| 情况 | 返回与副作用 |
|---|---|
| 同 ID、同指纹的已确认互动重试 | 204；即便原会话已关闭也不修改任何统计/活动/脏桶 |
| 同 ID、不同指纹 | 409 `event_conflict`；整个批次回滚 |
| 新 ID 引用不存在或不属于访客的页面 | 409 `page_view_missing`；不透露其他访客页面信息 |
| 新 ID 引用 closed、闲置到期或达到 12 小时的会话 | 409 `session_expired`；不写事件、不关闭/续期/复活会话、不改统计；关闭由独立成功事务完成 |
| 有效会话、该页尚未互动 | 写幂等事件，interacted=true，interactions 只加 1，最近活动单调更新 |
| 有效会话、该页已互动、换新 ID | 204 无副作用；不插入无界“重复互动”事件，不续活动 |

心跳先校验会话有效，再检查累计值；关闭会话的心跳始终返回 `session_expired`。SDK 丢弃旧页未确认互动；恢复时可创建 resume PV，但不能把旧互动改绑到新页面。批次中既有重复事件又有过期新互动时，按整批回滚原则返回错误，已有事实不受影响。

## 5. 历史日内同期比较（R02）

公开筛选仍使用站点自然日 `[start_date,end_date)`。当前日期被 `as_of` 裁剪。比较区间先向前平移相同数量自然日；如果当前末日尚未结束，上一周期末日也裁剪到相同本地墙钟时刻。每个区间各自转换为 UTC，不用固定秒数代替自然日。

夏令时规则固定为 `earlier_or_shift_forward`：重复墙钟时刻选择**第一次出现**；缺失墙钟时刻向后移动缺口长度，例如不存在的 02:30 映射到 03:30。当前 `as_of` 始终是真实瞬时值，不重新消歧；比较端应用此规则。不能仅依赖数据库/时区库的默认消歧。元信息记录两侧 UTC 边界、UTC offset、调整秒数与选择，界面注明可能不等秒数。

查询决策：

| 请求片段 | PV/UV/IP/新老 | 会话与比率 |
|---|---|---|
| 完整自然日 | PV 可用冻结日汇总；范围 UV/IP 用日成员集合 DISTINCT；新老读首次 PV 快照 | 按 started_at 归属；普通历史报表允许已经结算的完整会话 |
| 今日或历史部分日期 | PV 从 `[start,end)` 原始 page_view 事实计数，UV/IP 从同一集合 DISTINCT，新老按这些访客的 first_seen 快照 | started_at 在范围内；跳出/时长仅含 `status=closed AND closed_at <= comparison_as_of` |
| 完整日与部分日组合 | 完整日成员与部分日 PV 键 UNION 后一次 DISTINCT；不能相加 UV/IP；新老按整个范围起点分类 | 对整个比较侧统一应用历史关闭截止，不能拼入含未来关闭会话的全天标量 |

只有涉及部分末日的同期比较使用上述历史关闭截止，两侧必须采用相同口径；两个完整历史周期比较按当前一致快照读取最终已结算会话，不在各自期末截断。

`comparison_as_of` 是部分日比较该侧的有效截止瞬时值。对今日当前侧使用当前 `as_of`；历史比较侧使用历史截止。昨天 09:00 开始、11:30 才结算的会话，在昨天 10:00 的会话数里计 1，在已结束会话分母里计 0。`closed_at` 指实际后台处理时间，不用理论超时时刻伪造当时已结算；60 秒调度延迟及故障积压会影响比较。

截止时刻恰好发生的 PV 不计（`occurred_at < end`）；恰好关闭的会话计入（`closed_at <= comparison_as_of`）。跨午夜会话归开始日，后日 PV 仍归后日。新/老分类所需快照缺失时不可猜为新访客。

部分日期明细缺失返回相关指标 `null` 与 `partial_range_raw_unavailable`；关闭历史缺失返回 `historical_sessions_unavailable`；去重/身份窗口过期分别使用 `distinct_retention_exceeded`、`identity_history_unavailable`。其他可用指标照常返回。任一侧无数据能力时变化值为 null；真实基期为 0 则使用 `zero_baseline`。缺口、删除任务或跨 epoch 的不可用原因优先于“无流量”。

响应在原公共 meta 上增加以下字段；此为片段，具体边界必须由时区转换产生：

```json
{
  "comparison": {
    "mode": "previous_period_local_wall_clock",
    "previous_start_utc": "2026-11-02T00:00:00Z",
    "previous_end_utc": "2026-11-02T10:00:00Z",
    "comparison_as_of": "2026-11-02T10:00:00Z",
    "session_cutoff": "closed_at_lte_comparison_as_of",
    "dst_policy": "earlier_or_shift_forward",
    "dst_resolution": "exact",
    "dst_adjustment_seconds": 0,
    "current_utc_offset_seconds": 0,
    "previous_utc_offset_seconds": 0
  }
}
```

## 6. 完整替换与独立冻结（R05、R01）

普通聚合、冻结、保留清理和删除重建通过同一维护 advisory lock 串行调度；先取得专用连接上的维护锁，再开启业务事务并取站点锁，不能持站点锁等待维护锁。finally 解锁后才能归还连接。采集不获取维护锁；会话关闭仍用访客/会话行锁。单进程只用一个后台连接、轮转站点，锁键及连接占用随 R08/R10 实现验证。

重算使用短 `REPEATABLE READ` 事务，读取事实、成员、会话和脏版本 v 的一致快照，计算完整结果。小时总量和日总量采用覆盖写；**日页面与来源排行在同一事务先删除该站点该日期所有旧行，再插入全量新分组**。成员纠错/删除重建也按事实完整替换；共享 IP 若仍有其他访客 PV 必须保留。零值桶仍有总量、版本及覆盖记录，但排行可以为空。

同一发布事务设置 `metric_version / revision / computed_at / source_dirty_version`，日总量与排行共用 revision。按读到的 v 条件清脏；若版本不符或出现 `40001`，整桶回滚，重新取快照，有界退避重试。不能发布新结果再单独清脏，也不能以仅 upsert 排行替代完整替换。快照后的脏行并发更新会产生序列化失败，必须重试整笔事务。[隔离级别](https://www.postgresql.org/docs/17/transaction-iso.html#XACT-REPEATABLE-READ)

R08 可优化热桶发布策略，但必须保留以上可重跑、不丢变更、完整替换语义。首次实现不在扫描前锁热桶行阻塞采集；持续写入重试/延迟属于 M2 性能退出条件。

**到期冻结任务每 60 秒独立运行**，不能只消费 dirty_buckets。为站点已观测范围枚举小时和自然日，从持久化扫描游标补齐缺行（包括零流量日），并扫描已存在但未最终的桶。每轮至多 50 桶；失败项留在待处理集合，不能因为推进枚举游标而漏扫。重启继续补扫；暂停站点也继续结算、冻结和保留维护。

对桶 `[start,end)`，当数据库时间 `>= end+12h30min` 才有资格冻结；日 end 是下一本地午夜，小时 end 是下一 UTC 整点。资格不等于完成，必须同时满足：

1. 该桶覆盖从站点观测起点起无未知缺口；所需事实仍完整，或已有同版本、无后续变更的可信完整结果。不能将已清理事实重算为零。
2. started_at 在桶内的会话全部关闭；过去的页面不能再被新互动/心跳修改；无可回填该桶的采集事务（取锁后时间及 5 秒硬期限保证）。
3. 指标版本受支持、来源规则版本可解释；未来过滤规则变更不追溯修改旧事实；在同一快照内完成必要重算、总量/排行对账并清除读到的脏版本。
4. 同事务写 `is_final=true`、`finalized_at`、revision 和连续冻结水位。并发版本冲突回滚，不跳过失败桶推进水位。

无脏标记但到期的已有完整结果也必须冻结；从未访问的已观测日期生成明确的零值覆盖，首次建站前区间是 `before_site_created`。冻结后只有显式删除/纠错任务可失效该结果：先阻止报表/清理并登记缺口，再重建、对账、重新冻结；事实不足则保持不可用，禁止猜测补零。清理只能越过实际连续已冻结且覆盖可信的边界。
