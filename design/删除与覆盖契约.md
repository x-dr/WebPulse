# 删除、覆盖与恢复契约（M0）

版本：1.1.0；冻结日期：2026-11-04。处理 R06，配合 [统计与采集契约](统计与采集契约.md) 的站点锁、替换式重算和冻结协议。这里定义逻辑 Schema、状态转换与 API；具体 DDL 在 M1/M2 追加迁移，外部清单及恢复工具在 M4 交付。`001_init.sql` 与 `design/reference/` 不修改；它们不具备本契约全部状态。

## 1. 删除任务与身份

站点的 `public_id` 是跨备份稳定标识，永不复用；内部 bigint 只用于当前数据库关联。已删除标识在受限 `site_tombstones` 保留，恢复/新建时都检查。任务、清单、tombstone **不得以 ON DELETE CASCADE 依赖 sites**。运维指标 `job_state(name)` 继续保留，但不能替代逐次任务。

`deletion_jobs` 的逻辑字段与约束：

| 字段 | 类型/要求 |
|---|---|
| id / site_public_id | UUID 主键 / 不可变稳定站点标识；同站点至多一个未完成删除任务 |
| kind / schema_version | `site` 或 `visitor` / 正整数；保留清理使用自己的进度状态 |
| status | `queued`、`running`、`retry_wait`、`blocked`、`succeeded` |
| phase | `journal`、`facts`、`sessions`、`visitors`、`members`、`aggregates`、`site`、`verify`、`complete`，visitor 跳过 site |
| requested_at / cutoff_at | UTC；cutoff 是禁用排空后、站点锁内取得的接纳截止，固定不随重试移动 |
| idempotency_key / request_hash | 管理端提供 UUID；全局唯一；同键同规范化请求返回同任务，不同请求 409 |
| selector_ciphertext / encryption_key_id | 必要目标的带认证加密封装；密钥独立托管；不可在普通 API/日志返回 |
| cursor / cursor_version | 阶段专属、带版本的严格 JSON；只包含受限主键/日期游标，无原始 cid、IP、URL |
| attempts / next_attempt_at / last_error_code | 累计重试次数 / 可空时间 / 脱敏枚举，不保存 SQL/堆栈/载荷 |
| lease_owner / lease_expires_at / lease_generation | worker 租约及单调 fencing token；批次提交必须验证 token，旧 worker 不可继续写 |
| deleted_counts / result / completed_at | 同批提交的计数；结果含完成范围、重建/不可用范围、验证版本；成功才写完成时间 |
| journal_sequence / journal_ack_at | 独立删除清单的持久化确认；未确认禁止任何破坏性批次 |

`queued → running → succeeded`；暂时故障进入 `retry_wait`，退避到期继续原 phase/cursor；权限/密钥缺失或连续重试达上限进入 `blocked`，保留禁用与维护状态。管理员修复后重试同一任务。成功不可退回，重复执行只验证结果。不能在未恢复统计一致性时把任务标为成功或自动重新启用站点。

每批在一个事务中验证租约代数、执行有界删除、写新游标、累加计数并续租；失败整批回滚。按稳定主键 keyset 分页，不用 OFFSET；跨页依赖先删 interaction，再删 PV/page_views，再删 sessions、visitors，随后处理成员/汇总。游标格式含 `phase/table/last_key/upper_bound`；删除全过程站点不接收新写入，upper_bound 固定在任务范围。一个 worker 崩溃后，接替者取得维护锁和新租约代数，从最后提交的游标继续；另一个 worker 不能靠旧租约复活。

## 2. 受理、查询与单访客范围

DELETE `/sites/:site_id` 要求登录、CSRF、确认站点名和 `Idempotency-Key`。在冲突站点锁内禁用并原子建立任务/加密 outbox 意图，提交后返回 202。客户端超时重试用原键；站点已经删完时也能通过任务和 tombstone 返回原结果。相同站点不同删除请求在进行中返回现有 job_id；不同目标不能被无声合并。

```json
{
  "data": {
    "job_id": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa",
    "status": "queued",
    "phase": "journal"
  }
}
```

GET `/jobs/:job_id` 在站点已删除后仍可访问，仅向管理员开放；响应示例：

```json
{
  "data": {
    "job_id": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa",
    "site_id": "site_demo",
    "kind": "site",
    "status": "succeeded",
    "phase": "complete",
    "attempts": 1,
    "requested_at": "2026-11-04T02:00:00Z",
    "completed_at": "2026-11-04T02:01:00Z",
    "result": { "verified": true, "site_removed": true }
  }
}
```

运行中可返回各表已提交删除计数、next_attempt_at、脱敏错误码；不返回 selector、密钥、游标或伪造的百分比。未知任务 404；查询历史任务不依赖 sites 是否存在。首版仅有单管理员，后续授权必须保留任务所有者的稳定关联。

单访客删除是受限运维 CLI，首版不加公开删除访客端点。原 cid 通过禁止回显的标准输入提供，不能放命令行参数、shell 历史或日志；工具仅在内存用该站点所有相关 visitor key epoch 计算精确键列表。任务含不可变的 `{site_public_id, visitor_keys:[{epoch,key}], cutoff_at, scope:"all_observed_before_cutoff"}` 加密目标，删除截止前目标访客全部事实/会话/成员，不是只删一个日期上的 PV。

执行前取得维护锁、禁用排空并做 preflight：所有可能受影响且仍对外提供的汇总必须有足够原始 PV/会话重建依据，全部相关 epoch 密钥可用。若旧桶已失去访客归属、无法证明影响范围或精确重建，返回 `409 deletion_not_exact`，不执行破坏性删除；保持暂停供管理员确认后续操作。可明确选择另一个整站删除任务，不自动扩大授权范围。

删除要重建受影响的日/小时访客和 IP 成员、总量、页面/来源排行，保留其他访客共享的 IP。first_seen 记录按剩余事实与既定身份窗口处理，不猜测已丢失历史。完成后仍保持暂停，由管理员显式恢复；恢复后同 cid 的新事件在 cutoff 之后属于新接纳数据，删除不是永久封禁浏览器。

## 3. 可用覆盖、冻结与清理水位

`site_data_coverage` 每站点每数据层一行，层枚举为 `raw_pv|sessions|hour_members|day_members|hour_aggregates|day_aggregates`，唯一键 `(site_id, layer)`。层名称对应能力，不能用一组水位代表所有保留窗口。

| 字段 | 语义 |
|---|---|
| observed_from | 站点创建并具备接纳能力的 UTC 瞬时值；首日可能不完整 |
| available_from / available_through | 此数据层连续可信的半开区间；右端仅推进到已提交的覆盖；实时层在查询快照计算当前上限 |
| aggregated_through / finalized_through | 聚合层连续已发布/已最终的桶结束边界，非聚合层为 null |
| cleanup_target / cleanup_cursor | 本次清理的固定自然日目标及阶段/主键游标；中途不移动目标 |
| retention_version / revision / updated_at | 对应设置版本、每次状态变化递增的 revision、最后成功提交时间 |

站点创建事务同时创建各层覆盖，初始 `available_from=available_through=observed_from`。空站点也有可用边界；没有事件行不等于没有观测。冻结枚举另以 `(site_id, grain)` 为键保存 `next_bucket_start / last_scan_at`，处理成功才推进枚举游标，同时重扫已存在的非最终桶，避免失败项被跳过。小时和日枚举器补齐已观测的零桶；创建之前返回 `before_site_created`，不能编造建站前完整零日。冻结水位从观测起点开始，只越过连续成功桶。

额外 `coverage_gaps` 表记录 `(site_id, layer, start_utc, end_utc, reason, job_id, revision, resolved_at)`，范围必须非空；未解决缺口优先于外层连续水位。用于删除重建、故障、无法验证的恢复区间；任何命中缺口的指标不可声称 exact。重建和清除缺口与新 revision 同事务提交。零流量用有覆盖的零总量表达，不使用 gap。

清理顺序：持维护锁 → 读配置与实际覆盖 → 验证将失去重建依据的桶均已最终 → **先持久化本批目标区间不可查询的 gap** → 分批删除并提交游标 → 确认整个目标日期/层已清理 → 同事务推进 available_from、清除对应 gap、写清理成功水位。部分日期删除失败时仍保持 gap，不允许旧水位把部分事实宣称为完整；重启从游标继续。无数据批次也需按计划推进，不能用 `min(event_time)` 代替覆盖记录。

分批行数与耗时均有上限；不得跨过未冻结或删除待重建的日期。物理保留的跨日依赖行不扩大查询覆盖。增大保留天数不能恢复已删数据；缩短时预览目标日期、能力损失和实际水位，只有成功批次推进实际窗口。缓存键增加 coverage revision；失效后仍须查询检查站点维护状态，防止旧缓存绕过删除。

## 4. 删除清单、备份与恢复

数据库内 `deletion_outbox` 保存 task ID、schema_version、加密目标、独立 journal 序号和确认状态；不随站点删除。执行器先将意图持久化到**独立于数据库卷及备份轮转的受限加密清单存储**，校验后回写确认，再执行删除。外部记录以 task ID 幂等写入、认证完整性、单调序号可查；密钥 ID、nonce、密文和认证标签封装，不记录原 cid/IP/敏感 URL。API 运行角色无清单解密权。

意图包括 `site` 或 `visitor` 类型、稳定站点 public ID、cutoff 语义、精确 visitor key+epoch 列表（visitor 类型）、创建时间、任务/契约版本；整站删除使用永久站点 tombstone，删除该标识全部数据。完成记录追加执行结果，不覆写意图。数据库提交与异机写入不是分布式原子事务，因此必须先持久化意图、后删除；异机不可用时停在 journal 阶段，站点保持禁用，不假报完成。

`backup_inventory` 记录每份可恢复备份的 ID、快照时间、完成时间、校验值、密钥版本、存储位置及确认销毁时间；位置/凭据不对外暴露。清单与必要解密材料必须保留到所有可能包含目标数据的备份、人工副本和恢复副本确认销毁后。7 日只是默认备份轮转，不是无条件删除清单的 TTL；有遗留/失败轮转时继续保留。任务公开结果保留至少同样期限，站点 tombstone 永久保留最小随机标识。

恢复流程固定为：隔离实例并关闭采集/报表/SSE → 校验备份、迁移与 epoch 密钥 → 读取独立清单的最新完整序列 → 重放所有可能影响该快照的意图（含未完成任务，不能仅按“备份时间之后”筛选）→ 重建或标记不可用覆盖 → 对账及隐私断言 → 写恢复水位 → 允许开放。重放按 task ID 幂等；不存在目标也是成功。

恢复旧快照时，单访客删除先移除匹配键和 cutoff 的可关联事实/成员。如果旧快照缺少重建某段汇总的原始依据，保守将该站点 cutoff 之前不能证明安全的汇总区间登记为 `privacy_replay_unverifiable` 并禁止查询，而不是提供旧数字或猜测扣减。结果记录 withheld_ranges；这些范围不会因重启或后台聚合自动恢复。清单缺序、解密失败或目标 key epoch 缺失时，恢复入口始终保持关闭。恢复后的实际可用边界取已验证数据与清单影响的交集，不能按保留配置重新推导成完整窗口。

## 5. 迁移落点

| 阶段 | 必须补充的结构与验收 |
|---|---|
| M1 | sites 生命周期/配置版本、activity_seq/指纹版本、稳定 tombstone、deletion_jobs 与 outbox、站点锁与任务受理；单访客 CLI 不接收未经验证的 raw cid 输出 |
| M2 | site_data_coverage、coverage_gaps、汇总 revision/finalized_at/metric_version、冻结扫描游标；删除执行器、替换重建、分批恢复、清理预览 |
| M4 | 独立加密清单存储适配器、最小权限与密钥管理、backup_inventory、隔离恢复闸门及真实重放演练 |

M4 的独立清单尚不可用时，M1/M2 可以受理或用测试替身验证状态机，但生产删除执行器必须停在 journal 阶段；不能临时绕过确认。新增表和列以版本化迁移落地，迁移前验证既有数据与索引成本；本次 M0 不直接创建上述业务表。
